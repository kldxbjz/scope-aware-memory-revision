## 结论与建议

目前已经完成课程项目主实验，但如果希望论文更有说服力，优先需要补充的是**强基线、机制验证和泛化验证**。继续增加同类合成数据，未必能解决这些问题。

建议保留现有结果，优先考虑两项补充实验：

1. 直接读取原始历史的基线：检验学习式记忆系统相对原始证据的实际价值。
2. 固定已写好的记忆，比较原始与紧凑展示：检验 Scope 的收益是否来自查询时的呈现，以及能否降低读取成本。

**建议顺序：先做 A，再做 B，然后选择路线一做外部读取诊断。A/B 的实现可并行。原有 60 条类别审核已完成双人标注和第三人仲裁，额外 60 条保留备用，无需作为启动 A/B 的前置条件。**

人工改写对话的路线二不纳入当前计划。RL、完整新记忆架构和大规模重新生成训练集暂不优先。本文是讨论建议，不表示团队已经决定执行所有实验。围绕标注规模、数据数量和执行顺序的简明说明见《后续实验建议.md》。

## 1. 当前实验说明了什么

### 1.1 已有结果

| 评测集 | Scope − CRUD 的 QA 差值 | 解释 |
|---|---:|---|
| Dev | −2.5 个百分点，95% CI [−5.2, +0.3] | 没有显示 Scope 优势 |
| Challenge v1 | +0.4 个百分点，95% CI [−2.9, +4.0] | 没有明确差异 |
| Final test | +2.7 个百分点，95% CI [+0.9, +4.5] | 这份 test 上 Scope 整体系统领先 |
| Final test，不含 boundary probes | +1.7 个百分点，95% CI [−0.2, +3.4] | 去除时间边界题后，优势仍有不确定性 |

SFT 相对 Prompt 的提升明确，是目前最稳健的结果。Scope 整体系统在 final test 上领先，但优势没有在 dev 和 challenge 上稳定出现。

更关键的是：**gold memory 下 Scope 也领先约 2.7 个百分点。**事后分解中的写入残差约为 0，置信区间跨零。这与“优势主要与读取格式有关”的解释一致，但不能严格证明全部收益来自格式，也不能证明两种写入策略等效。

来源：[最终评测结果](https://github.com/kldxbjz/scope-aware-memory-revision/blob/ff120b331372daa8a293144b086861563df5f0d9/docs/evaluation.md#test-results-2026-11-24)、[事后分解](https://github.com/kldxbjz/scope-aware-memory-revision/blob/ff120b331372daa8a293144b086861563df5f0d9/docs/analysis.md#format-against-writing)。

### 1.2 需要补齐的证据

| 不足 | 为什么影响论文 |
|---|---|
| 缺少直接读取历史的强基线 | 目前不能回答：这么短的对话，是否直接读历史就足够？ |
| 写入、表示和读取效果混在一起 | 整体 QA 更高，不等于写入策略更好 |
| 只使用一个读取模型 | 优势可能依赖 Qwen3-4B 对特定格式的处理习惯 |
| 合成数据的变化范围有限 | 受控任务中的表现，不能直接推出真实个人助手中的效果 |
| Scope 成本较高 | 需要解释额外成本买到了什么，而不只是展示准确率 |

现有多 seed、冻结配置、episode/family bootstrap、gold references 和成本分析都应保留。补充实验应围绕上述具体缺口展开，而不是只增加实验数量。

## 2. 数据集的问题：覆盖范围，而不只是数量

主数据有 920 个 episode、5,466 个事件，来自 84 个场景家族的合成组合；不是 960 条。挑战集另计。

| 划分 | 时间线数量 | 事件数量 |
|---|---:|---:|
| train | 600 | 3,573 |
| dev | 120 | 702 |
| test | 200 | 1,191 |
| 合计 | **920** | **5,466** |

当前协议有以下限制：

- 每个 episode 只有 4–8 个事件、1–2 个偏好属性；
- 每个事件只有一种状态变化；
- 不包含重叠 scope 和优先级规则；
- 新值与新情境必须在用户对话中以已列出的表达出现。

因此，现有研究更接近：

> 在短、明确、可精确评分的偏好时间线上，训练模型执行两种记忆修订协议，并比较下游效果。

这个范围可以成立，但“复杂真实对话中的长期个性化记忆”需要更多证据。

是否需要更多训练样本，目前也不能确定，因为还没有学习曲线。即使增加数量，也不会自动增加隐含表达、长时间跨度和复杂状态变化的覆盖。因此，不建议立即再生成大量相同模式的数据。

来源：[数据说明](https://github.com/kldxbjz/scope-aware-memory-revision/blob/ff120b331372daa8a293144b086861563df5f0d9/training/scope_revision_v1/README.md)、[协议边界](https://github.com/kldxbjz/scope-aware-memory-revision/blob/ff120b331372daa8a293144b086861563df5f0d9/docs/protocol.md#10-trims-relative-to-outline-v27)。

检索截至 2026-11-24，重点核对原论文和官方数据说明。这是面向本项目问题的定向检索，不是穷尽性文献综述。以下经验用于设计补充实验，不保证相同改动在本项目中提高分数。

| 论文 | 原文中的相关发现或设计 | 对本项目的启发 |
|---|---|---|
| LongMemEval，ICLR 2025 | 即使检索到正确证据，读取策略和结构化呈现仍影响 QA；JSON 的效果还与读取提示有关 | “格式帮助读取”已有先例，需要进一步解释本项目特有的 scope 和时间边界问题。[§5.5](https://arxiv.org/html/2410.10813#S5.SS5) |
| MemDelta，2026-06，预印本 | 控制单个组件后，部分方法排名会变化；强调匹配模型、基线和写入成本 | 补强基线，并固定记忆内容后再比较读取方式。[§3–5](https://arxiv.org/html/2606.29914) |

| MAPE，2026-11-12，预印本 | 将 build、retrieve、compose、answer 分开；分析支持保留原始证据和改进查询时的证据组织 | 可以先改查询时的记忆展示，不必立即重训完整写入协议。[§2、§4.3](https://arxiv.org/html/2611.17068v1) |

## 4. 建议的补充实验

### 当前实现状态与执行顺序

最新核对到提交 `587525c060f835f9f41cf1b0e7c83bae533c9f81`：A/B 实现和运行方案已经加入仓库，入口为 `scope_memory/readtime.py`、`training/sft/reread.py`、`training/sft/submit_readtime.sh`。下一步先核对已有任务状态与 5 个 dev episode 的 smoke 检查，冻结配置并记录 `runs/readtime/FROZEN`，再进行或收集正式 dev/test 评测，避免重复提交队友已运行的任务。顺序仍为 A、B、外部读取诊断；A/B 的实现和运行组织可并行。代码存在不等于已完成评测或已经提高分数。

### 实验 A：直接读取原始历史的基线

**优先级最高。**

输入为初始已知偏好，加上截至当前 probe 的全部可见对话，让同一个 Answer Agent 回答同样的问题。不得加入未来事件、gold 状态、事件类别或答案。

与现有 CRUD SFT、Scope SFT 比较：

- QA，以及 target/default/neighbor/boundary 分组；
- 写入和读取的总 token、调用次数；
- “历史答对而记忆答错”与“记忆答对而历史答错”的数量。

它回答的问题是：

> 在当前短时间线上，学习式记忆系统相对直接保存证据，实际增加了什么价值？

如果历史基线表现很好，可以研究压缩和成本优势；如果 Scope 更好，就有更强的理由说明状态整理有价值。两种结果都能推进论文。

实现时需确保：

1. 历史严格截断到 probe 对应事件，且包含相同的初始已知信息；
2. 使用相同的题目、选项、读取模型和解码设置，必要的输入格式差异明确记录；
3. 报告实际输入长度及截断规则，不能让某组丢失关键证据；
4. 成本包含所有写入调用，不能只比较最后一次问答的 token。

设计动机参考：[Memory Tax §4](https://arxiv.org/html/2610.34073v1)、[MemDelta §3](https://arxiv.org/html/2606.29914)。

### 实验 B：固定记忆，比较读取呈现方式

**这是最有希望同时改善结果与解释力的轻量改进。**

复用已经保存的 rollout snapshots，让 Scope 的同一份记忆分别显示为：

| 条件 | 给 Answer Agent 看什么 |
|---|---|
| 原始 Scope | 当前完整记录格式 |
| 紧凑 Scope | 属性、偏好值、适用情境、有效期；去掉不影响当前答案的审计字段 |

紧凑呈现示例：

```text
属性：饮品
一般偏好：茶
考试周：低因咖啡；持续有效
```

要求：

- 所有取值、情境和日期都来自模型实际写出的记忆，错误也必须保留。
- 不得利用 gold 修复记录，也不能把正确适用的那条记录预先选出来。
- 只改变查询时的展示，不改变写入模型接收到的历史状态。
- 保留原本表达的偏好语义和有效期，不因压缩丢失必要信息。

先在 dev 调试并冻结展示规则，再做补充评测。有预算时，用一个预先选定的额外读取模型重读同一批记忆，同时重读 CRUD，检查排名是否稳定。

这个实验可以检验：

1. 紧凑展示是否降低读取 token，同时保持或提高 QA；
2. 当前优势是否主要出现在特定 reader；
3. 去掉审计信息后，Scope 的帮助是否仍然存在。

如果进一步把 CRUD 和 Scope 都转换成共同展示格式，必须报告转换覆盖率。转换失败的样本不能静默删除，否则会产生新的偏差。

**简化读取展示与简化写入动作是两个不同实验。**前者不需要重训，后者需要新的训练与公平对照。建议先完成前者，再判断是否值得运行 M3-Lite。

设计动机参考：[LongMemEval §5.5](https://arxiv.org/html/2410.10813#S5.SS5)、[MAPE §4.3](https://arxiv.org/html/2611.17068v1)。

### 小型泛化验证：选择路线一，外部读取诊断

**不需要人工重新制作逐事件类别标签或改写对话；需要少量质量抽查。**

从 MemSyco 的 Contextual Scope Control 和 Valid Memory Selection 中，按固定随机种子各抽 30 条，作为 60 条探索性诊断。

需注意：

- 该数据没有本项目所需的逐事件 CRUD 动作标签，不能直接作为同一个端到端写入实验。
- 若使用 gold memory，只能明确称为 oracle-memory 读取条件，不能声称检验了写入策略。
- `memory.policy`、`current/outdated` 判定标签、评分 rubric 和参考答案不能混入答案模型输入；也不能先按正确答案筛掉候选记忆。
- 不同呈现条件必须使用相同的可用记忆内容。
- 开放式答案使用官方评分规则和固定裁判配置；可先人工抽查约 10–20 条，覆盖两类任务和不同条件，发现系统性问题再扩大抽查。这是工作量建议，不是统计充分性的保证。

来源：[MemSyco 官方数据卡](https://github.com/XMUDeepLIT/MemSyco-Bench/blob/main/data/README.md)。

人工改写对话的路线二不纳入当前计划。外部 60 条与原先用于类别审核的 60 条用途不同；这项验证读取能力，不能证明训练过的写入模型已经泛化。60 条只能发现明显失败，无法可靠确认两三个百分点的小优势。预算允许时可以扩大自动评测范围。外部来源也不等于真实人类对话。

## 5. 人工分析与结果解释

### 已完成：60 条类别审核及仲裁

Raina 和队友 A 均完成同一批 60 条；原始一致为 58/60，一致率 96.67%，Cohen’s κ = 0.96。两处分歧由队友 C 裁定支持 A，Raina 已在对话中确认结果：L008 为 `stable_preference`，L024 为 `exception_revision`。采用 A 的全部 60 条作为最终人工类别，最终类别与原 gold 60/60 一致，本次无需改动生成标签。

两份原始标注分别保留，最终汇总为 `annotations/label_audit/labels_final.json`。C 的结果依据 Raina 的转述，本次没有收到 C 原始标注文件；不据此追认已核验的全程纯人工双盲流程。Raina 部分条目曾与 AI 讨论，应如实记录辅助来源。补充 60 条保留备用，不再将补齐第二份标注或扩到 120 条列为 A/B 的前置任务。

### 另行安排：模型错误归因与质量抽查

现有 Scope 40 条、CRUD 40 条错误归因是另一项工作，可与 A/B 并行安排。它可以帮助判断：紧凑展示后，减少的是读取错误，还是错误仍然来自写入。两位标注者先独立判断，原始判断与仲裁结果分别保存。

流程与材料：[人工错误分析方案](https://github.com/kldxbjz/scope-aware-memory-revision/blob/ff120b331372daa8a293144b086861563df5f0d9/docs/analysis.md#manual-error-analysis-pre-specified)。

类别审核的一致性不能替代对 scope、value、validity 和 probe 答案的检查，也不代表整个数据集没有错误。若后续出现系统性数据问题，再启用补充包并检查生成规则。

所有补充实验都发生在看到 final test 之后，应单独标为后续探索实验：

- 保留原始 test 结果及冻结配置；
- 对新实验预先固定主要对比、样本 ID、模型、呈现规则和预算；
- 重新读取旧 snapshots 会产生新的 Answer Agent 评测，应记录新条件和调用，不能覆盖原表；
- 报告改善、无变化和下降，不以必须提高原分数作为成功标准。

## 建议聚焦的后续研究问题

> 在相同偏好证据下，显式 scope 表示何时提高答案可靠性，其收益是否能在更换读取方式和表达分布后保留，并抵偿成本？

这个问题能把当前的正结果、负结果和成本放进同一个可检验框架。它是后续探索方向，不替代原定 H1/H2。

如果主要补充实验完成后仍有预算，可以考虑 M3-Lite 单 seed pilot。无需为了显得方法复杂而启动 RL、完整新架构或大规模重做数据。
