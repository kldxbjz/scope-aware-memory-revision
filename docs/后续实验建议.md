## 2. 合成数据是否只有 960 条，数量是否太少？

当前 v1.1 主数据集是 **920 段时间线、5,466 个事件**，不是 960 条。挑战集另计。

| 划分 | 时间线数量 | 事件数量 |
|---|---:|---:|
| 训练集 | 600 | 3,573 |
| 开发集 | 120 | 702 |
| 测试集 | 200 | 1,191 |
| 合计 | **920** | **5,466** |

训练面对的是数千个事件级修订机会。CRUD 和 Scope 是相同事件的两种投影，不能把两套投影相加，算成双倍独立样本。

**目前更明确的不足是覆盖范围有限；是否训练数量不足，尚缺学习曲线证据。**

这些时间线由 84 个场景家族组合而来，通常只有 4–8 个事件、1–2 个属性，不覆盖重叠情境和复杂优先级。继续使用相同生成方式扩到几千段，不会自动补上这些能力。

先完成 A/B 和小型外部诊断。若随后确实要判断更多训练数据是否有价值，再考虑用现有训练集的 150、300、600 段做学习曲线，保持数据划分及对照条件一致，并报告训练步数/计算量。无需先大规模重新生成数据。

依据：[主数据说明](https://github.com/kldxbjz/scope-aware-memory-revision/blob/ff120b331372daa8a293144b086861563df5f0d9/training/scope_revision_v1/README.md)。

## 3. 补充实验按什么顺序做？A/B 能否主要通过代码完成？

**可以。A/B 主要需要代码、读取模型推理、自动评分和统计，不需要新增人工类别标签，也无需重新训练写入模型。当前实现已经提交，下一步优先检查并运行已有流程，无需重复从头写一套。**

已有入口：`scope_memory/readtime.py`（输入与报告）、`training/sft/reread.py`（读取模型推理）和 `training/sft/submit_readtime.sh`（提交任务）；方案见 `docs/analysis.md` 的 Read-time experiments。先核对 5 个 dev episode 的 smoke 检查、`runs/readtime/FROZEN` 冻结标记及现有任务状态，再进行或收集 dev/test 正式评测，避免重复提交队友已经运行的任务。

| 顺序 | 实验 | 核心问题 | 人工投入 |
|---|---|---|---|
| 第一：A | 直接读取原始历史 | 当前短对话中，记忆系统相对直接读历史增加了什么价值？ | 抽查初始信息与历史截断，排除未来信息 |
| 第二：B | 固定记忆，比较完整与紧凑展示 | 展示方式影响多大，能否降低读取成本？ | 抽查转换是否保留必要语义 |
| 第三：路线一 | 外部读取诊断 | 相关读取现象能否在另一套数据中出现？ | 抽查输入转换和自动评分 |

A/B 的实现可以并行；先后是研究优先级，两项均应报告。不要根据 A 是否有利决定是否报告 B。

**A：**提供相同初始已知偏好和截至当前问题对应事件的完整可见历史，使用相同读取模型、问题、选项和解码设置。按已有答案自动评分，报告总体及分组 QA、总 token 和调用次数，并统计历史与记忆分别救回/损失了哪些题。必须实际调用模型回答。

**B：**复用已经保存的模型记忆 snapshots，只改变展示形式。模型写出的错误也要保留，不利用 gold 修复，不提前选择正确适用的记录，不改变写入模型接收的历史状态。比较相同问题的 QA 和读取 token；紧凑规则应由可复核的程序实现。

先在 dev 调试并冻结规则。原始 test 已经看过，新评测应单独标为后续探索实验，保留原来的测试结果和冻结配置。

## 4. 路线一是否需要重新标注？路线二是否可以取消？

**选择路线一；人工改写对话的路线二不纳入当前计划。**

MemSyco 已有参考答案、评分规则和官方评测程序，因此不用逐条补写 CRUD 标签或人工改写对话。它采用开放式回答和模型裁判，仍需少量人工检查评分是否可信。

建议按固定随机种子，从 Contextual Scope Control 和 Valid Memory Selection 各抽 30 条，固定同一批 60 条，比较普通展示与结构化展示。使用相同读取模型和相同记忆内容，复用官方评分规则，固定裁判配置；先人工抽查约 10–20 条，覆盖两类任务及不同条件，发现系统性问题再扩大抽查。这个抽查数量是工作量建议，不是统计充分性的保证。

使用官方 gold memory 时，明确称为 oracle-memory 读取诊断。只提供该条件允许的记忆内容，不把 `memory.policy`、`current/outdated` 判定标签、评分规则或参考答案混入答案模型输入，不先按正确答案筛掉候选记忆。两种展示必须保留相同的候选内容；任何结构转换都不能凭空加入答案信息。

这项验证读取能力，不能证明训练过的写入模型已经泛化；它不是原项目逐事件写入实验的直接替代。外部 60 条与原有审核 60 条用途不同。60 条适合发现明显失败，不能可靠确认两三个百分点的小优势；预算允许时可以扩大自动评测范围，无需等比例增加人工标注。

依据：[MemSyco 官方数据卡](https://github.com/XMUDeepLIT/MemSyco-Bench/blob/main/data/README.md)、[官方评测说明](https://github.com/XMUDeepLIT/MemSyco-Bench/blob/main/evaluation/README.md)。
